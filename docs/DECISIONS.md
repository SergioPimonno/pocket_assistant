# Журнал решений (ADR)

Формат: номер, дата, решение, почему, что отвергли. Новые решения добавляются в конец.

---

### ADR-001 · 2026-11-16 · Платформа: Android, целевое устройство Samsung Galaxy S25
**Решение.** Разрабатываем только под Android (minSdk 31, targetSdk — актуальный). Эталонное устройство — Galaxy S25: Snapdragon 8 Elite, 12 ГБ ОЗУ.
**Почему.** На iPhone нельзя:
- постоянно слушать слово активации в фоне;
- заменить системного ассистента;
- получить список установленных приложений и запускать их произвольно;
- отправлять SMS или звонить без участия пользователя;
- ставить приложение вне App Store без ограничений.

Ключевые функции секретаря на iOS невозможны.
**Отвергнуто.** iPhone 17 Pro; кроссплатформа (Flutter/KMP-UI) — лишняя сложность без выигрыша. Позже можно выделить логику в Kotlin Multiplatform, но это не цель.

### ADR-002 · 2026-11-16 · Нативный Kotlin + нативные движки
**Решение.**
- UI — Kotlin + Jetpack Compose.
- LLM — llama.cpp через JNI (GGUF; поддержка LoRA-адаптеров и грамматик GBNF).
- Речь — sherpa-onnx: слово активации, STT, TTS в одной библиотеке.
- Плагины — QuickJS.

**Почему.** Лучшая скорость, офлайн, работа в фоне и полный доступ к Android API.

### ADR-003 · 2026-11-16 · Основная LLM на телефоне — 3–4B, квантование Q4/Q5
**Решение.** Основная модель — 3–4 млрд параметров, около 2,5–3 ГБ. Конкретную модель выбираем бенчмарком P0-03 из актуальных моделей с хорошим русским (семейства Qwen, Gemma, русские дообучения вроде Vikhr / T-lite).
**Дополнительно (P4-10).** Модель 7–8B (~5 ГБ) для режима «подумай глубже» офлайн. Владелец подтвердил: место под неё выделяем, общий бюджет ~9–11 ГБ.
**Почему.** Секретарские задачи требуют скорости и надёжного вызова инструментов, а не глубоких рассуждений. Сложное уходит на сервер.

### ADR-004 · 2026-11-16 · Гибрид: телефон + сервер владельца
**Решение.** Когда есть сеть, телефон подключается к серверу владельца через приватную сеть (Tailscale или WireGuard). На сервере работают:
- большая LLM;
- агент глубокого веб-поиска;
- маршрутизация;
- дообучение;
- дополнительные модули.

Что делать локально, а что на сервере, решает роутер на телефоне.
**Почему.** Владельцу важен гибкий глубокий онлайн-поиск. Тяжёлые вычисления на телефоне нереалистичны.

### ADR-005 · 2026-11-16 · Персонализация: мгновенная на телефоне + периодическая на ПК/сервере
**Решение.** Адаптация к речи и стилю владельца работает офлайн и идёт в два слоя:
1. **Мгновенно, на телефоне:**
   - память фактов;
   - профиль стиля общения;
   - ночная «рефлексия»;
   - словарь владельца и hotwords для STT;
   - журнал исправлений.
2. **Периодически, на ПК/сервере:**
   - LoRA-дообучение LLM на диалогах;
   - дообучение STT на голосе владельца.

Готовые адаптеры загружаются на телефон и дальше работают офлайн.
**Железо для обучения.** Пайплайн `training/` должен поддерживать бэкенды CUDA, Apple MPS/MLX и CPU. Владелец хочет обучать на CPU ноутбука: для STT и LLM 3–4B это реально (часы для STT, одна-две ночи для 4B). Для 7–8B используется GPU. Основной вариант — рабочий сервер владельца с NVIDIA A5000 (24 ГБ), который используется временно (см. ADR-009). Запасные — домашний сервер или почасовая аренда.
**Отвергнуто.** Полноценное дообучение на телефоне — медленно и греет устройство. Может быть исследовано позже (P9-07, экспериментально).

### ADR-006 · 2026-11-16 · Плагины на JS в песочнице с подтверждением
**Решение.** Новые навыки — JS-плагины в QuickJS-песочнице:
- манифест с разрешениями;
- доступ только к API ассистента, без прямого доступа к Android;
- установка или обновление только после подтверждения владельцем на экране просмотра (код + разрешения);
- версии с откатом.

Плагины может генерировать LLM (на сервере или на телефоне).

### ADR-007 · 2026-11-16 · Режимы вывода: голос / текст
**Решение.** Единый диалог в чат-интерфейсе. Режим ответа: `voice` / `text` / `auto`. В режиме `auto` голос включается, когда подключены наушники или ассистент вызван голосом, и выключается в беззвучном режиме. Переключать можно кнопкой, голосом или правилом.

### ADR-008 · 2026-11-16 · Сервер `dxv` не подходит для тяжёлых модулей
**Факты.** Ubuntu 24.04, 1,9 ГБ ОЗУ (свободно ~1 ГБ), swap нет, GPU нет, диск 50 ГБ (свободно 37 ГБ). Уже работают: ledscheme (Java + Postgres), dxvfix-website (Node/PM2), dxvsite (Node), nginx, caddy.
**Решение.** На `dxv` не размещаем LLM, Playwright, GraphHopper/Valhalla и обучение: их ОЗУ не поместится и мешало бы работающим сервисам. Где будут тяжёлые модули — ждёт выбора владельца (ПК с GPU / VPS 16–32 ГБ / аренда GPU для обучения). `dxv` можно использовать как лёгкий шлюз (≤ 300 МБ), если понадобится всегда доступная точка входа.

### ADR-009 · 2026-11-16 · Дообучение на временно доступном GPU-сервере (A5000)
**Решение.** Обучение упаковано в переносимый пакет (`training/`):
- Docker-образ или venv;
- архив датасета;
- одна команда запуска;
- на выходе — LoRA-адаптеры, модель STT и отчёт eval.

Пакет должен работать на чужой машине без установки системных пакетов, а при необходимости и без интернета: веса базовых моделей привозятся с собой.
**Приватность.**
- Датасет (диалоги, записи голоса) хранится на сервере только в зашифрованном виде.
- После обучения рабочая папка удаляется командой `cleanup`.
- С сервера уносятся только артефакты.
- Владелец сам отвечает за согласование использования рабочего сервера.

**Ориентиры на одной A5000:** STT — 10–30 мин, LoRA 3–4B — 30–60 мин, LoRA 7–8B — 1–3 ч.

### ADR-010 · 2026-11-16 · Разработка без телефона: эмулятор Android на ПК
**Контекст.** Телефона у владельца пока нет.
**Решение.**
- Разработка и ручная проверка идут в эмуляторе Android Studio (образ x86_64, Android 14+, Google APIs/Play). Микрофон и динамик пробрасываются с ПК, звонки и SMS имитируются консолью эмулятора.
- В эмуляторе используется маленькая dev-модель 0,5–1,5B: x86-эмулятор в разы медленнее S25. Код от размера модели не зависит.
- Качество моделей (понимание команд, распознавание, голоса) оценивается на ПК теми же движками: llama.cpp, sherpa-onnx. Скорость на S25 замеряется позже (P0-03b, P0-04b) и может поменять выбор модели, но не архитектуру.
- Логика (оркестратор, инструменты, память, роутер) пишется в модулях на чистом Kotlin/JVM и покрывается unit-тестами без эмулятора.

**Риск.** Производительность и нагрев на реальном телефоне узнаем поздно. Смягчение — бюджет задержки в P1-06 и запасная модель меньшего размера.

### ADR-011 · 2026-11-16 · Постоянный сервер — минимальный CPU-VPS, обучение на рабочих серверах
**Контекст.** Дообучение идёт на рабочих серверах владельца (Threadripper, A5000 + A4500), они используются временно (ADR-009). Постоянному серверу GPU не нужен. Владелец хочет минимальные расходы.
**Решение.** Постоянный сервер — VPS **4 vCPU / 8 ГБ RAM / 100+ ГБ NVMe** (например, VDSina Standard: 4 ядра, 8 ГБ, 150 ГБ, 2 400 ₽/мес). Профиль развёртывания `min`.

Бюджет памяти:

| Компонент | Память |
|---|---|
| ОС и Docker | ~0,7 ГБ |
| gateway + sync | ~0,3 ГБ |
| SearXNG | ~0,3 ГБ |
| загрузчик + Playwright (1 вкладка за раз) | ~1 ГБ |
| GraphHopper (только регион владельца) | ~1,5 ГБ |
| LLM 3–4B Q4 (та же, что на телефоне; ~5–8 токенов/с) | ~3 ГБ |
| **запас** | ~1 ГБ |

Каждому контейнеру задаются лимиты памяти, swap 4 ГБ.

**Ограничения профиля `min`.**
- Сводки глубокого поиска и генерация плагинов делает модель 3–4B: качество среднее, ответ ~20–60 с.
- Маршруты только по региону, не по всей стране.
- Задачи выполняются по очереди.

**Путь роста** (без изменения кода, сменой профиля):
- `mid` — 4–8 vCPU / 16 ГБ: LLM 7–8B на сервере. Лучшее соотношение цены и качества, если найдётся у провайдера.
- `cpu` — VDSina Dedicated 1 (8 ядер / 30 ГБ, 9 870 ₽): LLM 14B.

Дорогой вариант откладываем, пока не станет ясно, что качества `min` не хватает.
**Домашняя альтернатива VPS** (разовая покупка вместо аренды): Raspberry Pi 5 (8–16 ГБ, NVMe через HAT, активное охлаждение) или б/у офисный мини-ПК x86 (16 ГБ, SSD). Профиль `min` должен работать на обоих, поэтому все Docker-образы сервера собираются под **linux/amd64 и linux/arm64**. На Pi 5 модель 3–4B даёт ~2–4 токена/с: сводки поиска пойдут в 2–3 раза медленнее, чем на VPS.
**Отвергнуто.** Домашний сервер с GPU — не нужен, раз обучение на рабочих серверах. GPU-тарифы VDSina — дорого и мало видеопамяти. `dxv` — 1,9 ГБ RAM, занят (ADR-008).
