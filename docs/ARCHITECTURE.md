# Архитектура

## Общая схема

```
ТЕЛЕФОН (Galaxy S25, всегда)                     СЕРВЕР ВЛАДЕЛЬЦА (когда есть сеть)
───────────────────────────────                  ─────────────────────────────────
 ┌ AssistantService (foreground) ┐                ┌ gateway (FastAPI, WebSocket) ┐
 │ WakeWord → VAD → STT          │                │  auth по ключу устройства    │
 │        ↓                      │                └──────────────┬───────────────┘
 │ Orchestrator ── Router ───────┼── Tailscale ──►  big LLM (vLLM / llama.cpp)
 │   │  LLM 3–4B (+LoRA)         │   WireGuard      search-agent (SearXNG, fetch,
 │   │  Tools (Intents, API)     │                    Playwright, обход ссылок)
 │   │  Memory (SQLite+vec)      │                  routing (GraphHopper/Valhalla)
 │   │  Plugins (QuickJS)        │                  plugin-builder
 │   ↓                           │                  training (LoRA LLM, STT)
 │ Output: TTS | текст (Compose) │                  sync (память, логи, адаптеры)
 └───────────────────────────────┘
```

## Модули Android (`android/`)

| Модуль | Ответственность |
|---|---|
| `app` | UI на Compose: чат, переключатель голос/текст, настройки, экраны подтверждений, просмотр плагинов |
| `core:service` | `AssistantService` (foreground), `VoiceInteractionService` (ассистент по умолчанию), жизненный цикл |
| `core:speech` | sherpa-onnx: KWS (слово активации), VAD, STT (streaming), TTS; hotwords и словарь владельца |
| `core:llm` | JNI-обёртка llama.cpp: загрузка GGUF, LoRA-адаптеры, стриминг токенов, грамматики GBNF для вызова инструментов, KV-кэш системного промпта |
| `core:tasks` | Менеджер задач (ADR-012): очередь, приоритеты, состояния, хранение, восстановление; управление ресурсами (P1-08) |
| `core:orchestrator` | Цикл диалога: контекст → LLM → вызовы инструментов → ответ. Сборка промпта: профиль стиля + релевантная память + история |
| `core:router` | Выбор, где обрабатывать запрос: `local` или `server`. Офлайн-очередь задач |
| `core:tools` | Встроенные инструменты (см. ниже), реестр `ToolSpec`, политика подтверждений |
| `core:memory` | SQLite (SQLCipher) + sqlite-vec + модель эмбеддингов: факты, эпизоды, профиль стиля, журнал исправлений, логи для обучения |
| `core:plugins` | QuickJS-рантайм, манифесты, разрешения, версии и откат |
| `core:sync` | Клиент протокола, синхронизация, загрузка адаптеров и моделей |
| `core:models` | Менеджер моделей: скачивание и проверка (sha256), выбор активных, учёт места |

## Контракт инструмента (`ToolSpec`)

Источник истины — `shared/protocol/tools/*.json` (JSON Schema). Агенты не меняют формат без обновления этого документа.

```json
{
  "name": "set_alarm",
  "description": "Поставить будильник",
  "parameters": { "type": "object", "properties": { "time": {"type": "string", "format": "time"}, "label": {"type": "string"} }, "required": ["time"] },
  "confirm": "never | always | if_ambiguous",
  "where": "local | server | any"
}
```

- LLM вызывает инструменты строго по схеме. Корректный JSON гарантируется ограниченной генерацией (GBNF-грамматика строится из схемы).
- Результат инструмента — JSON `{ "ok": bool, "data": ..., "say": "короткая фраза для пользователя" }`.

**Встроенные инструменты (этап 2):**
- будильник и таймер;
- напоминания (по времени и по месту);
- календарь (чтение и запись);
- заметки;
- задачи;
- контакты;
- звонок, SMS — только с подтверждением;
- список и запуск приложений;
- фонарик, громкость, режимы;
- маршрут: `build_route{origin?, destination, waypoints[], mode, avoid[], prefs}` → Intent в Яндекс Карты / Google Maps / Organic Maps;
- поиск по данным на телефоне;
- время и погода из кэша.

## Задачи (ADR-012)

Любое поручение — задача с единой моделью на телефоне и сервере:

```
Task { id, kind, priority: interactive|normal|background, state, where: phone|server|device:<id>,
       created_at, deadline?, parent_id?, payload, result?, attempts }
state: queued → running → (waiting_user | waiting_network | waiting_resources) → done | failed | cancelled
```

- Интерактивные задачи вытесняют фоновые за LLM. Одновременно идёт одна генерация LLM на телефоне.
- Быстрые задачи выполняются корутинами в процессе. Длительные идут через WorkManager и переживают перезапуск.
- Состояние задач с `priority ≥ normal` хранится в SQLite.

## Журнал событий и пакеты поведения (ADR-014)

- Телефон пишет компактный журнал значимых событий: исправления, решения, принятые и отклонённые предложения, итоги поисков. Журнал ограничен по объёму и сроку хранения.
- Сервер (P5-07) и ночная рефлексия (P4-05) выпускают **пакеты поведения** `{type, version, base_version, payload, sha256, eval_report}`. Тип — `style_profile`, `rules`, `interest_map`, `search_strategy`, `lora`, `stt_adapter`.
- Телефон применяет пакет, только если совпадает `base_version`. Предыдущие 3 версии хранятся для отката.

## Проверка фактов в поиске (P6-07…P6-09)

`план → поиск → чтение → извлечение утверждений → поиск первоисточников и опровержений → граф происхождения (оригинал / перепечатка) → оценка доказательств → вывод со степенью уверенности и пометкой непроверенного`

## Протокол «телефон ↔ сервер»

- Транспорт: WebSocket поверх приватной сети (Tailscale или WireGuard), плюс TLS. Авторизация — ключ устройства, выданный при сопряжении (QR-код).
- Сообщения — JSON со схемами в `shared/protocol/`:
  - `task.submit {id, kind: chat|search|route|plugin_build, payload, context}`;
  - `task.progress {id, stage, text?}`;
  - `task.clarify {id, question, options?}` — сервер задаёт уточняющий вопрос;
  - `task.answer {id, answer}` — ответ пользователя на уточнение;
  - `task.result {id, say, text, sources[], attachments[]}`;
  - `sync.push/pull` — память, логи диалогов, исправления;
  - `artifact.available {type: lora|stt_adapter|model|plugin, version, url, sha256}`.
- Задачи переживают обрыв связи: сервер хранит результат, телефон забирает его при переподключении.

## Сервер (`server/`)

| Модуль | Что делает |
|---|---|
| `gateway` | WebSocket и REST, авторизация, очередь задач |
| `llm` | Большая модель (vLLM или llama.cpp server, OpenAI-совместимый API). Размер зависит от GPU |
| `search_agent` | План запросов → SearXNG → загрузка страниц (httpx; Playwright для JS-сайтов) → извлечение текста → обход вложенных ссылок (глубина 2–3, бюджет страниц) → ранжирование → сводка с источниками. Политика уточнений: не больше 1–2 вопросов, только если неоднозначность влияет на результат |
| `routing` | GraphHopper или Valhalla с OSM-данными региона и пользовательскими профилями («через парки», «меньше светофоров», «без платных дорог») → список точек или GPX |
| `plugin_builder` | Генерация JS-плагина по описанию, статическая проверка, тесты в песочнице |
| `training` | Сбор датасетов из логов, LoRA для LLM → GGUF-адаптер, дообучение STT, eval-гейт, публикация артефактов |
| `sync` | Хранение копии памяти и логов, выдача артефактов |

## Персонализация (ADR-005)

| Слой | Где | Когда | Что |
|---|---|---|---|
| Память фактов | телефон | сразу | извлечение фактов из диалога → SQLite + векторы |
| Профиль стиля | телефон | сразу / ночью | текстовый профиль (тон, длина, обращение, юмор), подставляется в системный промпт |
| Рефлексия | телефон | ночью на зарядке | LLM перечитывает день и обновляет профиль и память |
| Словарь речи | телефон | сразу | имена, названия, слова владельца → hotwords STT; исправления → правила |
| TTS-манера | телефон | сразу | скорость, голос, паузы, короткие или развёрнутые ответы — из профиля |
| LoRA LLM | ПК/сервер | раз в 2–4 недели | дообучение на одобренных диалогах → адаптер 10–100 МБ |
| Адаптация STT | ПК/сервер | по мере накопления | дообучение на записях голоса с исправленными расшифровками |

## Бюджет места на S25 (ориентир)

| Компонент | Размер |
|---|---|
| LLM 3–4B Q4/Q5 | 2,5–3 ГБ |
| LLM 7–8B (опционально) | ~5 ГБ |
| STT (крупная модель + стриминговая) | 0,3–1,5 ГБ |
| TTS, 2–3 голоса | ~0,3 ГБ |
| Эмбеддинги + KWS + VAD | ~0,2 ГБ |
| Адаптеры, память, логи | 0,2–1 ГБ |
| **Итого** | **~4–6 ГБ без 7–8B, ~9–11 ГБ с ней** |
