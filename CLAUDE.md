# Инструкции для агентов проекта

Проект: личный голосовой ассистент-секретарь для Android. Работает офлайн. Когда есть сеть, подключается к серверу владельца.
Рабочее название — `assistant` (владелец может переименовать).

Прочитай перед работой:
1. `docs/PLAN.md` — этапы, задачи, статусы, критерии готовности.
2. `docs/ARCHITECTURE.md` — компоненты, интерфейсы, протокол «телефон ↔ сервер».
3. `docs/DECISIONS.md` — принятые решения (ADR). Не пересматривай их без явного запроса владельца.

## Главные принципы

- **Offline-first.** Всё из этапов 1–4 и 8 должно работать на телефоне без сети. Сервер — ускоритель и расширение, а не зависимость. Если сервер недоступен, ассистент деградирует штатно: говорит об этом, ставит задачу в очередь или выполняет упрощённо.
- **Приватность.** Данные пользователя (речь, диалоги, память, контакты, SMS) уходят только на сервер владельца по защищённому каналу. Никаких сторонних облачных API, телеметрии и аналитики. Исключение — веб-поиск на сервере: туда уходят только поисковые запросы.
- **Подтверждение опасных действий.** Звонки, отправка SMS и сообщений, удаление данных, установка или обновление плагинов, любые траты требуют явного подтверждения пользователя голосом или кнопкой.
- **Экономия ресурсов.** Фоновая работа не должна заметно расходовать батарею: тяжёлое — на зарядке или на сервере. Память, журналы и кэши имеют явные лимиты и сроки хранения.
- **Измеримость и откат.** Любое изменение алгоритмов, правил поведения, стратегий поиска и моделей имеет метрику в `eval/`, версию и способ отката. Без измеримого улучшения не внедряется.
- **Независимость суждений.** Ассистент подстраивает стиль под владельца, но не подстраивает факты: если владелец ошибается, он вежливо возражает (ADR-013).
- **Русский язык — основной.** Интерфейс, голос и тестовые наборы на русском. Код, идентификаторы, коммиты и комментарии в коде — на английском. Документация в `docs/` — на русском.
- **Владелец — программист, но Kotlin не знает.** Пиши идиоматичный, но читаемый Kotlin без «магии». Нетривиальные места коротко поясняй в комментариях. В описании PR объясняй, что сделано и как это проверить на телефоне.

## Рабочий процесс

- Работа ведётся **локально** в папке владельца `development-pocket-assistant`. GitHub — для контроля версий. Владелец правит код вручную, поэтому перед работой — `git status` и `git pull`, чужие незакоммиченные правки не затирать.
- Владелец на Windows: команды для него — Git Bash или PowerShell. Окончания строк задаёт `.gitattributes`.
- Контекст, которого нет в плане (железо, предпочтения, открытые вопросы), — в `docs/HANDOFF.md`.

## Как брать и закрывать задачи

- У каждой задачи в `docs/PLAN.md` есть ID (`P2-04`) и статус: `todo` / `in-progress` / `review` / `done` / `blocked`.
- Бери задачу со статусом `todo`, у которой все зависимости `done`. Сразу ставь ей `in-progress` и добавляй пометку `(агент: <ветка>)`.
- Ветка: `<ID>-<кратко>`, например `p2-04-app-launcher`. Одна задача — одна ветка — один PR.
- **Definition of Done:**
  - код собирается: `./gradlew assembleDebug` для Android, `pytest` для сервера;
  - есть тесты на логику;
  - для голосовых и LLM-функций добавлены примеры в `eval/`, и eval не просел;
  - статус в `PLAN.md` обновлён;
  - новое решение архитектурного уровня записано в `DECISIONS.md`.
- Если задача требует действия владельца (проверить на телефоне, записать голос, дать доступ), ставь `blocked` и опиши в `PLAN.md` → «Ждёт владельца», что именно нужно.
- Не меняй публичные интерфейсы из `ARCHITECTURE.md` (`ToolSpec`, протокол, формат плагинов) молча. Сначала обнови документ, потом код.

## Структура репозитория (целевая)

```
android/          Kotlin-приложение (Gradle, модули core/*)
server/           Python 3.12, FastAPI, модули сервера
shared/protocol/  JSON Schema / OpenAPI протокола и инструментов (источник истины)
eval/             тестовые наборы и скрипты оценки (команды, STT, стиль)
training/         пайплайны дообучения (LoRA для LLM, STT) — запускаются на ПК/сервере
docs/             план, архитектура, решения
```
